# 커밋 규칙

이 문서는 git 커밋의 단위, 시점, 메시지 형식을 정한다. 모든 커밋은 [작업 관리 규칙](TaskRule.md)의 작업 ID에 묶인다. 메시지 형식(3절)은 [커밋 메시지 검사기](VerificationTools.md#10-커밋-메시지-검사기)가 검증하고, 커밋 단위와 시점(2절)은 작업자가 지킨다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## 1. 목적

커밋 이력만 보고도 각 변경이 어떤 작업(로드맵 태스크, 이슈, 핫픽스)에서 나왔는지 알 수 있게 한다. 커밋의 작업 ID로 [로드맵](Roadmap.md)·[이슈](Issue.md)의 할 일과 [완료](Done.md)의 상세 기록을 찾아갈 수 있다.

## 2. 커밋 단위와 시점

- 커밋 하나는 하나의 작업(또는 함께 처리한 몇 개의 작업)의 변경만 담는다. 서로 관계없는 작업의 변경을 한 커밋에 섞지 않는다.
- 작업을 끝내면 [완료 처리](TaskRule.md#43-완료)까지 마친 상태로 커밋한다. 그래서 완료 커밋에는 코드·문서 변경과 함께 로드맵·이슈의 `[x]`, 완료 기록이 들어간다.
- 작업이 길면 진행 중(`[~]`)에도 중간 커밋을 한다([기록 보존](TaskRule.md#45-기록-보존)). 이때도 [검증 도구](VerificationTools.md)가 통과하는 상태에서만 커밋한다. 코드 작업이면 [목업](CodeRule.md#1-문서-우선-작업-절차)을 만들어 검사가 통과하는 상태로 만든 뒤 커밋한다.
- 아직 시작하지 않은(`[ ]`) 작업의 ID로는 커밋하지 않는다.
- 커밋은 작업 브랜치에서 하고, 커밋하면 바로 원격에 push한다. `main`에는 직접 커밋하지 않으며, `main` 반영은 사용자가 PR을 병합해서 한다([PR 규칙](PullRequestRule.md)).

## 3. 메시지 형식

```text
<작업 ID>[, <작업 ID>…][(진행 중)]: <요약>

<본문 (선택)>

<트레일러 (선택)>
```

**제목 줄**

- 작업 ID로 시작한다. 여러 작업이면 `, `로 구분해 모두 적는다. `I1-I5` 같은 범위 표기나 `M0` 같은 마일스톤만의 표기는 쓰지 않는다. 같은 ID를 두 번 쓰지 않는다.
- 작업이 끝나지 않은 상태의 중간 커밋(진행 중 기록, 목업)은 ID 바로 뒤에 `(진행 중)`을 붙인다.
- 그 뒤에 `: `(콜론과 공백 하나)를 쓰고 요약을 적는다.
- 요약은 이 커밋이 한 일을 한국어 한 문장으로 적고, 마침표를 찍지 않는다.
- 제목 줄은 72자 이하로 쓴다.
- 작업 ID는 [로드맵](Roadmap.md)이나 [이슈](Issue.md)에 있어야 한다.

**본문**

- 제목 다음에 빈 줄 하나를 두고 쓴다.
- 무엇을 왜 바꿨는지 요약한다. 상세 내역은 완료 기록에 있으므로 반복하지 않는다.

**트레일러**

- `Co-Authored-By:` 같은 git 트레일러는 본문 뒤에 빈 줄을 두고 쓴다.

예:

```text
M1-T2: 로그인 화면과 세션 저장 구현

로그인 폼과 세션 토큰 저장을 추가했다. 토큰이 만료되면
로그인 화면으로 돌아간다.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## 4. 예외

- 병합 커밋은 검사하지 않는다. git이 만드는 제목(`Merge `, `Revert `, `fixup! `, `squash! `로 시작)도 형식을 따르지 않아도 된다.
- 이 규칙이 생기기 전의 커밋이 있는 저장소는 [설정](VerificationTools.md#11-설정)의 `check.commit_baseline`에 기준 커밋을 적는다. 기준 커밋과 그 이전 커밋은 검사하지 않으며, 기존 이력은 고쳐 쓰지 않는다. 처음부터 이 규칙으로 시작한 저장소는 비워 둔다.

## 5. 강제

- `.githooks/commit-msg` hook이 커밋할 때마다 [커밋 메시지 검사기](VerificationTools.md#10-커밋-메시지-검사기)로 메시지를 검사하고, 규칙에 맞지 않으면 커밋을 막는다. 설치와 `core.hooksPath` 설정은 [자동 실행](VerificationTools.md#9-일괄-실행과-자동-실행)에 있다.
- hook을 우회하는 `git commit --no-verify`는 쓰지 않는다. 우회된 커밋이 있어도 이력 검사([6. 검증](#6-검증))에서 드러난다.

## 6. 검증

기준 커밋 이후의 모든 커밋 메시지를 검사한다. 이 이력 검사는 [검증 도구](VerificationTools.md#1-실행-방법)의 일괄 검사에 들어 있어, 작업을 끝낼 때와 커밋할 때, CI에서 함께 실행된다.
