# 문서 작업 규칙

이 문서는 프로젝트의 모든 문서 작업에 적용되는 규칙이다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## 1. 문서 우선 원칙

- 프로젝트의 작업은 **문서 작업**과 **코드 작업** 두 축으로 이루어진다. 두 축은 [포인터 규약](Traceability.md)으로 연결된다.
- 문서는 코드 작업의 규칙이다. 코드는 문서를 따르며, 문서가 코드를 따르지 않는다.
- 작업 순서는 항상 **문서 작성·수정 → 문서의 지시에 따른 코드 작성**이다. 코드 쪽 절차는 [코드 작업 규칙](CodeRule.md#1-문서-우선-작업-절차)에 있다.
- 코드를 먼저 변경한 뒤 문서를 코드에 맞추는 일은 하지 않는다.
- 문서와 코드가 어긋나면 문서가 기준이다. 코드를 문서에 맞게 고치거나, 의도가 바뀐 것이라면 문서를 먼저 고친 뒤 코드를 고친다.
- 프로젝트의 모든 규칙은 `CLAUDE.md`를 루트로 하는 프로젝트 내 문서에서만 관리한다. 사용자가 새 방침을 지시하면 이 문서들에 반영한다. 에이전트 도구의 개인 메모리(Claude Code 메모리 등)나 저장소 밖의 파일에 규칙을 두지 않는다. 그런 곳의 내용은 다른 작업자와 다른 환경에서 보이지 않고, 문서와 어긋나도 검사할 수 없기 때문이다.
- 기계적으로 검사할 수 있는 규칙·형식·ID 체계를 새로 정하거나 바꾸면, 그것을 검사하는 검사기를 같은 작업 안에서 [검증 도구](VerificationTools.md)에 명세하고 구현한다. 검사기를 나중으로 미루거나 선택 사항으로 남기지 않는다.

## 2. 형식

- 모든 문서는 마크다운(`.md`)으로 작성한다.
- 문서는 `docs/` 폴더 아래에 둔다. 예외는 루트의 두 문서다.
  - `CLAUDE.md`: 진입 문서([7. 진입 문서](#7-진입-문서)).
  - `README.md`: 저장소를 처음 보는 사람을 위한 소개와 사용법(무엇인지, 설치·실행 방법, 기본 정보). 프로젝트와 사용자·개발자와 코딩 에이전트를 잇는 문서다. 사람은 README로 프로젝트를 처음 만나고, 에이전트는 사용자에게 안내할 사용법을 README에서 찾는다. 규칙과 설계는 적지 않고 `docs/`의 문서로 링크한다. 같은 내용이 README와 규칙 문서에 함께 있으면 어긋나도 알 수 없기 때문이다.
    - README가 있으면 [문서 인덱스](index.md)에서 링크한다([4. 고아 문서 금지](#4-고아-문서-금지)).
    - README에 적힌 내용(소개, 설치·실행 방법, 명령, 버전 등)을 바꾸는 작업은 같은 작업 안에서 README도 고친다. 작업을 마치기 전에 README가 바뀐 내용과 맞는지 확인한다.
- 각 문서는 `#` 제목 하나로 시작하고, 첫 문단에 문서의 목적을 적는다.
- 하위 제목은 `## 1. 제목`처럼 번호를 붙인다. 앵커가 짧고 안정적이 된다.
- 경로와 파일 이름에는 공백을 쓰지 않는다.

## 3. 링크 규칙

- 문서 간 참조는 마크다운 링크 문법 `[문서 이름](문서 path)`를 사용한다.
  - 예: `[문서 인덱스](index.md)`
- path는 링크를 거는 문서 위치 기준의 상대 경로로 쓴다.
- 문서 이름만 텍스트로 언급하지 말고, 반드시 링크로 건다.
- 문서의 특정 절을 가리킬 때는 `[이름](문서.md#앵커)`를 쓴다. 앵커는 제목에서 다음 순서로 만든다.
  1. 제목 안의 인라인 코드 기호(`` ` ``)를 지우고, 링크는 표시 이름만 남긴다.
  2. 영문자를 소문자로 바꾼다.
  3. 문자(한글 포함)·숫자·`_`·`-`·공백이 아닌 문자를 지운다.
  4. 공백을 `-`로 바꾼다.
  5. 같은 문서에 같은 앵커가 이미 있으면 뒤에 `-1`, `-2` …를 붙인다.
  - 예: `## 3. 링크 규칙` → `#3-링크-규칙`
- 코드를 가리키는 링크(코드 포인터)는 [포인터 규약](Traceability.md#2-문서에서-코드로-가는-포인터)을 따른다.
- 코드 블록과 인라인 코드 안의 링크는 예시로 보고 검사하지 않는다. 링크 형식을 예시로 보여 줄 때는 반드시 코드 표기 안에 쓴다.

## 4. 고아 문서 금지

- 고아 문서란 [문서 인덱스](index.md)에서 링크를 따라 도달할 수 없는 문서를 말한다. `docs/` 아래 문서와 루트의 `README.md`가 대상이다. 진입 문서 `CLAUDE.md`는 인덱스보다 먼저 읽으므로 대상이 아니다.
- 고아 문서가 있어서는 안 된다.
- 새 문서를 만들면 같은 작업 안에서 [문서 인덱스](index.md) 또는 인덱스에서 도달 가능한 상위 문서에 링크를 추가한다.
- 새 문서에는 상위 문서(최소한 [문서 인덱스](index.md))로 돌아가는 링크를 포함한다.
- 문서를 삭제하거나 이름·경로를 바꾸면, 그 문서를 가리키던 모든 링크를 함께 수정한다.

## 5. 문서 추가 절차

1. `docs/` 아래에 마크다운 문서를 만든다.
2. 이 규칙의 형식과 링크 규칙에 맞게 작성한다.
3. [문서 인덱스](index.md)의 해당 작업 분류(문서 작업 / 코드 작업)에 링크와 설명을 추가한다.
4. 아래 6절의 검증을 실행한다.

## 6. 검증

문서 작업을 마치면 [검증 도구](VerificationTools.md#1-실행-방법)의 일괄 검사 `<projinit> check`를 실행한다. [문서 링크 검사기](VerificationTools.md#3-문서-링크-검사기)가 깨진 링크와 고아 문서를, [포인터 검사기](VerificationTools.md#4-포인터-검사기)가 코드 포인터를, [작업 관리 검사기](VerificationTools.md#6-작업-관리-검사기)가 작업 관리 문서를 검사한다.

## 7. 진입 문서

진입 문서 `CLAUDE.md`는 문서 체계의 루트다. 작업자가 가장 먼저 읽으며, 어떤 문서부터 어떤 순서로 읽는지만 정한다. 구체적인 규칙·절차·명령은 하나도 두지 않고 모두 하위 문서로 보낸다. 같은 내용이 진입 문서와 하위 문서에 함께 있으면 둘이 어긋나도 알 수 없기 때문이다.

진입 문서는 다음 형식만 쓴다.

- 첫 줄은 `#` 제목이고, 그 다음에 목적을 적은 문단 하나가 온다.
- 그 뒤에는 `##` 제목과 한 줄짜리 `- ` 목록 줄만 온다. 목록 줄마다 `docs/` 아래 문서로 가는 링크가 하나 이상 있어야 한다.
- 코드 블록, 인라인 코드, 표, 번호 목록, 그 밖의 문단은 쓰지 않는다.
- [문서 인덱스](index.md)로 가는 링크가 있어야 한다.

구체적인 내용을 진입 문서에 넣고 싶어지면, 그 내용이 속할 하위 문서를 찾아 거기에 적고 진입 문서에는 그 문서로 가는 링크만 둔다. 이 형식은 [문서 링크 검사기](VerificationTools.md#3-문서-링크-검사기)가 검사한다.
