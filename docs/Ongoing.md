# 진행 중

이 문서는 지금 진행 중인 작업의 상세 내역을 적는다. 작업을 시작하면 항목을 추가하고, 끝나면 항목을 [완료](Done.md)로 옮기고 이 문서에서 지운다. 기록 형식과 흐름은 [작업 관리 규칙](TaskRule.md#4-작업-흐름)을 따르며, 할 일 목록은 [로드맵](Roadmap.md)과 [이슈](Issue.md)에 있다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## I3 진행 중 → 완료 이관 때 세부 내용 소실을 막는 규칙과 검사 (이관 보존 검사, 완료 기록 필수 절 확대)

- 시작일: 2026-10-31
- 근거 문서: [작업 관리 규칙](TaskRule.md#45-기록-보존)

### 계획
- 작업 관리 규칙에 기록 보존 규칙(덧붙이기만, 그대로 옮기기, 지우지 않기)과 기록 보존 검사 형식을 추가한다.
- 진행 중 기록에 `계획` 절, 완료 기록에 형식의 모든 절을 필수로 한다.
- 작업 관리 검사기에 `HEAD`와 비교하는 기록 보존 검사를 추가하고 테스트를 쓴다.

### 진행 기록
- 2026-10-31: 사용자가 진행 중 → 완료 이관 때 세부 내용이 소실되지 않도록 하는 규약과 절차가 있는지 물었다. 기록이 통째로 사라지는 것은 잡지만 옮기며 일부가 빠지는 것은 못 잡고, 완료 기록의 필수 절이 형식보다 적다는 것을 확인해 등록했다.
- 2026-10-31: 검사기는 현재 상태만 보므로 옮기기 전과 비교할 기준이 필요했다. 기준을 git `HEAD`로 정했다. pre-commit이 이미 모든 커밋에서 검사하므로 커밋 단위 보호가 된다.

### 결정 사항
- 비교는 줄 단위 포함 관계로 한다. 순서와 절 위치는 보지 않는다. 덧붙이기는 허용하고 고치기와 지우기는 막는다.
- 진행 중 기록에서 보존 대상은 진행 기록과 결정 사항뿐이다. 계획과 변경 파일은 작업 중에 바뀌는 것이 자연스럽다.
- 완료 기록 전체를 보존 대상으로 한다. M0-T5에서 완료 문서를 마일스톤별로 나누면 이 검사도 보관 문서를 함께 보도록 고쳐야 한다.
- 이 보호는 커밋된 내용에만 걸린다. 그래서 진행 중 기록은 작업 도중에도 커밋해 두라는 규칙을 함께 적었다.
