## I6 문서 우선 단계의 의도된 포인터 검사 실패 때문에 pre-commit이 진행 중 기록 커밋을 막는 충돌 해소

- 시작일: 2026-10-31
- 완료일: 2026-10-31
- 근거 문서: [코드 작업 규칙](CodeRule.md#1-문서-우선-작업-절차), [포인터 규약](Traceability.md#8-목업-표시)

### 계획
- 코드 작업 절차를 "문서 → 목업 → 구현"으로 바꾼다. 코드에 없는 심볼로는 코드 포인터를 걸지 않는다.
- 포인터 규약에 목업 표시 `@stub: <작업 ID>`를 정하고, 포인터 검사기가 표시한 작업이 진행 중인지 검사하게 한다.
- 이 작업 자체를 새 절차대로 한다: 문서를 고치고, 새 심볼의 목업을 만들어 진행 중 상태를 커밋한 뒤 구현한다.

### 진행 기록
- 2026-10-31: I5 중에 발견해 등록했다. 문서를 먼저 고치면 아직 없는 코드를 가리키는 포인터가 일부러 실패하고, pre-commit이 그 상태의 커밋을 막아 I3의 "진행 중 기록은 작업 도중에도 커밋한다"를 지킬 수 없었다.
- 2026-10-31: 사용자가 해결책을 제시했다. "진행 초기에 목업 코드를 만들어 두고 진행 중에 코드를 만들면 된다. 목업도 안 만들면 진행 중이 아니다. 목업조차 만들기 전에는 문서 → 코드 포인터를 만들지 않으면 된다."
- 2026-10-31: 목업도 검사를 통과하므로 구현하지 않은 목업이 남은 채 완료될 수 있다는 구멍이 있어, 목업에 작업 ID 표시를 달고 그 작업이 진행 중인지 검사하기로 했다.
- 2026-10-31: 새 절차대로 했다. 문서를 고치자 아직 없는 `check_stubs`를 가리키는 포인터가 실패했고, `@stub: I6` 표시를 단 목업을 만들자 모든 검사가 통과해 진행 중 상태를 커밋할 수 있었다(54bedab).
- 2026-10-31: `ModuleIndex.stubs` 수집과 `check_stubs`를 구현하고 목업 표시를 지웠다. 통과 요약에 남은 목업 수를 적어 할 일 목록으로 보이게 했다.

### 결정 사항
- 목업 표시는 `@stub: <작업 ID>`이며 `@doc:`과 같은 자리(주석, Python docstring)에 쓴다. 주석이라 개발 언어와 무관하다.
- 표시한 작업이 `[~]`가 아니면 오류다. 그래서 표시가 남아 있으면 완료할 수 없고, 남은 표시 목록이 기존의 "의도된 실패 목록"을 대신하는 할 일 목록이 된다.
- 검사는 코드 분석이 필요하므로 포인터 검사기에 둔다. 작업 상태는 작업 관리 검사기의 공개 함수로 읽는다.

### 변경 파일
- `docs/CodeRule.md`, `docs/TaskRule.md`, `docs/Traceability.md`, `docs/VerificationTools.md`, `docs/Issue.md`, `docs/Ongoing.md`
- 추가: `tools/code_index.py`, `tools/check_pointers.py`, `tests/test_check_pointers.py`, `docs/Done.md`

### 결과
- 코드 작업은 문서 → 목업 → 구현 순서로 하며, 문서 단계에서도 모든 검사가 통과해 진행 중 기록을 언제든 커밋할 수 있다.
- 구현하지 않은 목업(`@stub:` 표시)이 남아 있으면 작업을 완료할 수 없다. 남은 목업 수는 포인터 검사기의 통과 요약에 나온다.

- 이 보호는 커밋된 내용에만 걸린다. 그래서 진행 중 기록은 작업 도중에도 커밋해 두라는 규칙을 함께 적었다.

### 결정 사항
- 파서: tree-sitter와 언어별 문법 패키지. Python도 같은 방식으로 파싱해 경로를 하나로 둔다.
- 지원 언어: Python, JavaScript, TypeScript(TSX 포함), Rust, C, C++, Go, Java. [포인터 규약](Traceability.md#7-언어별-심볼-규칙)에 표로 둔다.
- 한정 이름의 구분자는 언어와 무관하게 `.`이다.
- 주석 포인터의 소속 규칙을 바꿨다. 이제 주석과 정의 사이에 빈 줄이 올 수 없다. 대신 파일의 첫 코드보다 앞에 있는 주석은 파일에 속한다. Python 밖의 언어에서 모듈 포인터를 달 곳이 필요하기 때문이다.

- 심볼 분류는 정의, 값, 네임스페이스 셋이다. 네임스페이스는 커버리지 대상이 아니며 그 안쪽은 바깥과 같은 수준으로 본다.
