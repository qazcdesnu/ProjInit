# 자료 폴더 설계

이 문서는 프로젝트 밖에서 가져온 자료를 두는 두 폴더, 참고 자료 폴더 `reference/`와 기존 프로젝트 폴더 `legacy/`를 왜 이렇게 정했는지와 작업 범위를 적는다(M6-T1). 규칙 자체는 공통 문서인 [자료 폴더 규칙](../MaterialRule.md)에, 검사기 구현은 [검사기 설계의 자료 폴더 검사기](Checkers.md#15-자료-폴더-검사기)에 있다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

## 1. 배경

[제품 비전의 기능 후보](../ProductVision.md#7-이후-기능-후보)에는 처음에 "참고 프로젝트를 `proto/`에 넣고 초기화한다"가 하나로 적혀 있었다. 사용자는 두 가지를 구분해야 한다고 했다(I19). 개발 중에 계속 참고하고 갱신하는 자료와, ProjInit 없이 작업하던 기존 프로젝트는 성격이 다르다. 전자는 살아 있는 자료이고, 후자는 넣는 순간 아카이브가 된다.

## 2. 결정

| 결정 | 이유 |
| --- | --- |
| 이름은 `reference/`와 `legacy/` | `reference`는 "참고 자료"를 그대로 뜻한다. `archive`는 완료 기록 보관(`Done-M<n>.md`)과 헷갈리고, `legacy`는 "ProjInit 이전의 프로젝트"라는 뜻이 바로 드러난다. `proto`는 시제품으로 읽혀 둘 다에 맞지 않는다. |
| 두 폴더 모두 `docs/` 밖, 루트에 둔다 | 자료는 문서가 아니다. `docs/`에 두면 고아 문서·링크 검사가 PDF나 남의 코드까지 문서로 다루게 된다. |
| 폴더마다 목록 문서(`docs/Reference.md`, `docs/Legacy.md`)를 두고 모든 파일을 링크하게 한다. I23에서 `reference/`는 강제를 뺐다 | 에이전트는 인덱스에서 링크를 따라 읽는다. 목록에 없는 자료는 없는 것과 같다. 폴더 링크를 허용해 파일이 많은 자료도 한 줄로 적을 수 있게 한다. |
| 목록 문서의 이름은 고정, 폴더 위치는 설정 | 작업 관리 문서처럼 공통 규칙이 정하는 이름이다. 폴더는 기존 저장소 구조와 부딪칠 수 있어 `paths.reference`, `paths.legacy`로 바꿀 수 있게 한다. |
| `legacy/`의 불변은 `HEAD`와 비교한다 | 완료 기록 보존([작업 관리 규칙 4.5](../TaskRule.md#45-기록-보존))과 같은 방식이다. pre-commit이 막으므로 커밋된 기존 프로젝트를 바꾸는 커밋은 만들어지지 않는다. 새 프로젝트를 새 하위 폴더로 넣는 것은 허용한다. |
| `legacy/` 안의 `.git`은 금지 | 저장소 안의 저장소는 내용이 커밋되지 않아 아카이브가 비어 버린다. |
| 자료 폴더 안 코드 파일 링크는 포인터가 아니다 | 포인터는 역방향 `@doc:`을 요구하는데, `legacy/`는 고칠 수 없고 자료는 이 프로젝트의 코드가 아니다. 파일이 있는지만 검사한다. |
| 초기화는 폴더를 만들지 않는다 | 빈 폴더는 git에 남지 않고, 필요 없는 프로젝트가 대부분이다. |
| 첫 작업은 `legacy/`가 있으면 먼저 읽는다 | 기존 프로젝트로 시작하는 흐름은 별도 명령 없이 "폴더에 넣고 `init`, `/start`"로 충분하다. `init`은 만들 파일이 이미 있을 때만 거부하므로 `legacy/`가 있는 폴더도 초기화할 수 있다. |
| `reference/`는 목록을 강제하지 않는다(I23) | 사람이 자료를 넣고 커밋하자 목록 문서가 없어 커밋이 막히고, 커밋하지 않은 변경 때문에 갱신도 막혔다. 참고 자료는 쓸 수도 안 쓸 수도 있는 살아 있는 자료라 넣을 때마다 목록을 쓰게 하는 것은 과하다. 목록에 올렸다고 에이전트가 읽는다는 보장도 없다. `legacy/`는 한 번 넣는 아카이브라 목록 한 줄이 부담이 아니어서 그대로 둔다. |
| 자료를 쓰게 하는 것은 세션 시작 hook으로 한다(I23) | 목록 강제 대신, 에이전트가 자료가 있다는 것을 기억에 의존하지 않고 알게 한다. SessionStart hook은 매 세션과 맥락 압축 뒤에 자료 목록을 맥락에 넣는다. 작업을 시작할 때 무엇을 참고했는지는 진행 중 기록의 `참고 자료` 줄에 남긴다. 이 줄은 처음에는 규칙으로만 두고 검사하지 않는다. |
| 로컬 자료 폴더 `private/`를 따로 둔다(I24) | 보안 때문에 저장소에 올리면 안 되지만 로컬 작업에서는 봐야 하는 자료가 있다. `reference/`에 섞으면 커밋되고, 아무 데나 두면 에이전트가 모른다. 이름은 "공유하지 않는다"는 뜻이 바로 드러나는 `private`로 한다. `local`은 뜻이 모호하고, `secret`은 키와 비밀번호를 넣는 곳으로 읽힌다. |
| `private/`는 링크하지 않는다, 선택 링크도(I24) | 사용자가 정했다. 다른 컴퓨터와 CI에는 파일이 없어 링크가 깨지고, 링크에 파일 이름이 남아 커밋된다. 선택 링크는 깨짐은 막지만 이름이 남는 것은 못 막는다. 경로가 필요하면 인라인 코드로 적는다. 같은 이유로 목록 문서도 두지 않고, 세션 시작 안내가 로컬에서만 알려 준다. |
| `.gitignore`에는 줄 하나만 보장한다(I26) | I24에서는 초기화가 이미 있는 파일을 만들 수 없다는 이유로 검사만 했다. 그러나 `.gitignore`는 파일 전체가 아니라 `/private/` 줄 하나만 있으면 되므로, 초기화와 갱신이 그 줄이 없을 때만 더한다. 사용자가 할 일이 없다. 자료 폴더 검사기는 줄을 지웠거나 강제로 스테이징한 경우의 안전망으로 남는다. |
| 모델로의 전송은 막지 않고 규칙에 적는다(I24) | `private/`의 목적은 저장소와 원격에 올리지 않는 것이다. 에이전트가 읽으면 내용은 모델로 간다. 에이전트도 보면 안 되는 비밀은 넣지 말라고 규칙에 적는다. |
| 첫 작업은 `reference/`에 자료가 있어도 먼저 읽는다(I22) | 개발에 앞서 모은 자료로 시작하는 흐름도 기존 프로젝트와 같다. "폴더에 넣고 `init`, `/start`"로 충분하며 별도 명령이 없다. |
| 목록 문서는 자료 폴더 규칙과 템플릿 인덱스가 선택 링크로 가리킨다(I22) | 목록 문서는 있을 수도 없을 수도 있어 [선택 링크](../DocumentationRule.md#3-링크-규칙)에 맞는다. 공통 문서인 자료 폴더 규칙이 가리키므로, 이미 초기화한 프로젝트도 갱신만 하면 인덱스를 고치지 않고 목록 문서가 도달 가능하다. |
| 자료는 근거, 결정은 문서(I22) | 자료는 길고 바뀌며 남이 쓴 것이다. 에이전트가 작업마다 자료 전체를 다시 읽지 않도록, 정한 것은 프로젝트 문서에 옮겨 적고 자료를 링크한다. 코드의 `@doc:`도 자료가 아니라 그 문서를 가리킨다. |
| 바로 읽는 형식만 넣기를 권한다(I22) | 에이전트는 텍스트, PDF, 이미지를 바로 읽지만 워드·엑셀·한글 같은 파일은 그대로 읽지 못한다. 형식은 검사하지 않는다. 원본을 함께 두고 싶은 경우가 있어서다. |

목록 항목의 형식(설명, 출처, 넣은 날짜)은 규칙에 권장으로만 적고 검사하지 않는다. 자료마다 적을 것이 달라 형식을 고정하면 오히려 쓰기 어렵기 때문이다.

## 3. 작업 범위

M6-T1 하나로 한다.

- 공통 규칙 문서 [자료 폴더 규칙](../MaterialRule.md)을 템플릿에 더한다. 진입 문서, 문서 작업 규칙, 포인터 규약, 작업 관리 규칙(4.8절), 검증 도구(2, 3, 4, 11, 15절), 템플릿 인덱스를 고친다. 이미 초기화한 프로젝트는 인덱스가 갱신되지 않지만, 새 규칙 문서는 문서 작업 규칙에서 링크하므로 고아 문서가 되지 않는다.
- 설정에 `paths.reference`, `paths.legacy`를 더한다([검사기 설계의 설정](Checkers.md#11-설정)).
- 자료 폴더 검사기를 만들고 일괄 실행에 넣는다. 문서 링크 검사기와 포인터 검사기가 자료 폴더 안 코드 파일 링크를 다루는 방식을 바꾼다.
- README에 기존 프로젝트로 시작하는 방법을 적고, 버전을 `0.1.5`로 올린다.

I22는 참고 자료를 넣고 쓰는 방법을 보강한다. 사용자가 개발에 앞서 모은 자료를 Claude가 참고하게 하는 방법의 설명이 부족하다고 했다.

- 자료 폴더 규칙 2절(목록 문서의 선택 링크, 항목의 "쓰는 곳")과 3절(넣는 것, 형식, 넣는 방법, 쓰는 방법, 고치고 지우기)을 고친다. 작업 관리 규칙 4.8절, 검증 도구 15절, 템플릿 인덱스를 고친다.
- 검사기는 바꾸지 않는다. 목록 문서의 선택 링크는 I21의 선택 링크 해석으로 동작한다.
- README에 참고 자료와 함께 시작하는 방법을 적고, 버전을 `0.1.8`로 올린다.

I23은 `reference/`의 목록 강제를 빼고 세션 시작 안내를 더한다.

- 자료 폴더 규칙 2, 3, 5절, 작업 관리 규칙 4.1과 5절, 검증 도구 1, 8, 9, 15절과 새 16절을 고친다. `.claude/settings.json` 템플릿에 SessionStart hook을 더한다.
- 자료 폴더 검사기는 `legacy/`만 목록을 검사한다. 새 하위 명령 `context`([검사기 설계의 세션 시작 안내](Checkers.md#16-세션-시작-안내))와 강제 장치 검사기의 SessionStart hook 검사를 더한다.
- 갱신 명령의 거부 메시지에 `git stash -u`를 쓰는 방법을 더한다.
- README를 고치고 버전을 `0.1.9`로 올린다.

I24는 로컬 자료 폴더 `private/`를 더한다.

- 자료 폴더 규칙에 5절을 더하고(세션 시작 안내와 검증은 6, 7절로), 진입 문서, 문서 작업 규칙 3절, 검증 도구 2, 3, 11, 15, 16절, 템플릿 인덱스를 고친다.
- 설정에 `paths.private`를 더한다. 문서 링크 검사기가 로컬 자료로 가는 링크를, 자료 폴더 검사기가 git에서 빠지지 않거나 추적된 로컬 자료를 보고한다. 세션 시작 안내에 로컬 자료를 더한다.
- README를 고치고 버전을 `0.1.10`으로 올린다.

I26은 초기화와 갱신이 `.gitignore`에 로컬 자료 폴더 줄을 넣게 한다([템플릿 구성 설계의 초기화 명령](Templates.md#9-초기화-명령)). 자료 폴더 규칙 5절, 작업 관리 규칙 4.8절, 검증 도구 15절과 README를 고치고 버전을 `0.1.11`로 올린다.
