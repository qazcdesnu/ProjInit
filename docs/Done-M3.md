# 완료 보관 M3 갱신

이 문서는 닫힌 마일스톤 M3의 완료 기록을 보관한다. M3의 태스크는 모두 취소되었다. 기록 형식은 [작업 관리 규칙](TaskRule.md#5-기록-형식)을 따르며, 아직 닫히지 않은 마일스톤의 기록은 [완료](Done.md)에 있다.

## I9 초기화 중심으로 제품 비전과 로드맵 재정비 (부품 명령만 두고 갱신 기능은 후보로)

- 시작일: 2026-10-31
- 완료일: 2026-10-31
- 근거 문서: [제품 비전](ProductVision.md#3-핵심-요구사항)

### 계획
- 제품 비전을 초기화 중심으로 고친다. 갱신 기능과 참고 프로젝트 초기화는 이후 기능 후보로 둔다.
- 사용자가 쓰는 명령은 `init` 하나로 하고, `check`와 `commit-msg`는 hook이 쓰는 부품으로 정리한다.
- 갱신 마일스톤(M3)의 태스크를 취소하고, M1-T3의 범위를 줄인다.

### 진행 기록
- 2026-10-31: 사용자가 물었다. "일단 초기화 기능만 생각했는데 왜 이렇게 여러 명령어를 벌써 생각했어? 난 그냥 초기화만 먼저 주문한 거고, 나중에 진행된 프로젝트를 proto 폴더에 넣으면 그걸 보고 초기화할 수 있게 하는 기능들을 차차 넣으려고 했는데."
- 2026-10-31: `init`·`check`·`upgrade` 명령과 "유지가 가장 중요한 가치"라는 요구사항은 M0-T1 때 AgentVis 대화에서 옮겨 온 제품 비전에 있던 것이고, 사용자에게 지금 무엇부터 만들지 확인하지 않은 채 계획을 넓혀 왔다는 것을 설명했다. `check`·`commit-msg`는 초기화된 프로젝트의 hook이 검사기를 실행하는 부품이라 필요하고, `upgrade`는 별개 기능이라는 구분과 함께 초기화 중심의 재정비를 제안했고, 사용자가 그대로 진행하라고 했다.
- 2026-10-31: 제품 비전의 핵심 요구사항 1·2와 7, 구성 초안, 명령 문단을 고치고 7절 "이후 기능 후보"를 만들었다. 패키지 구성 설계의 명령 표에서 단일 검사 하위 명령과 `upgrade`를 뺐다. M1-T3 설명을 줄이고, M3의 세 태스크를 취소했다.
- 2026-10-31: M3의 태스크가 모두 `[x]`(취소)가 되어 M3이 닫혔으므로, 보관 규칙대로 M3 태스크 기록과 이 이슈 기록을 `docs/Done-M3.md`에 두었다.

### 결정 사항
- 사용자가 쓰는 명령은 `init` 하나다. `check`, `commit-msg`는 hook용 부품으로 남긴다. 이게 없으면 초기화할 때 검사기를 프로젝트마다 복사해야 하는데, 이는 구성 초안이 피한 방식이다.
- 갱신(`upgrade`)과 참고 프로젝트로 초기화(`proto/`)는 제품 비전의 이후 기능 후보로 둔다. 넣기로 정하면 그때 마일스톤을 만든다.
- 로드맵 줄은 지우지 않는다는 규칙에 따라 M3 태스크는 취소로 처리했다. M3 마일스톤 제목은 그대로 둔다.
- 앞으로는 제품 비전에 있더라도 사용자가 주문하지 않은 기능으로 계획을 넓히기 전에 확인한다.
